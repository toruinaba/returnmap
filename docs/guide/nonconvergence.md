# 非収束の扱い

1 ステップの応力更新は、収束しないことがある。このページは、収束の判定、収束しなかった場合の手当て、層ごとの受け取り方を示す。実行できる例は [応答を計算する](simulation.md) の 6 節にある。

設定は integrator の `raise_on_nonconverged` の 1 つである。driver は、自身の外側の反復 (`StressDriver`、`MixedDriver`) の失敗にも同じ設定を用い、独自の設定を持たない。

| 層 | 非収束の受け取り方 |
|---|---|
| integrator | 既定は `RuntimeError`。`raise_on_nonconverged=False` の場合は、`converged=False` の結果を返す |
| driver | `iter_run` は、非収束のステップを返して停止する。`run` は、完了したステップのみを返し、`converged`、`failed_step` で知らせる |
| `fit_params` | 非収束の評価を、有限の大きな値として採点し、最適化を継続する。全評価が失敗した場合のみ例外になる ([フィッティングの設定](fitting.md) の 6 節) |
| `run_simulation` (サービス) | 途中までの履歴と、`converged`、`failed_step` を値で返す ([サービスに組み込む](service.md) の 3 節) |
| `compare_models` | 収束しなかったモデルを、`converged=False` の行として返し、他のモデルの比較を継続する ([モデルを比べる](comparing.md) の 3 節) |

呼び出しの誤り (引数の形の不一致など) は、どの層でも例外になる。

## 1. 収束の判定

| 項目 | 規定 |
|---|---|
| 許容値 | `tol × max(1, ‖σ_trial‖_∞)`。単位 (MPa、Pa) に依存しない |
| Δλ < 0 | 非収束として扱う。残差の系は Δλ < 0 の側にも根を持つが、負の塑性乗数は KKT 条件に反する (塑性ひずみが逆行する)。残差のノルムでは区別できないため、符号で判定する。増分が大きく、試行応力が許容される枝の外に出た場合に生じる |
| 非有限の値 | `inf`、`nan` を含む結果は、非収束として扱う |
| 手書きの解法の結果 | 同じ条件で判定する。閉形式の解は、どの入力に対しても値を返すためである。Δλ < 0 と非有限の値は、`converged=True` と報告されていても非収束として扱う |
| 非収束のステップの接線 | 弾性接線である (`raise_on_nonconverged=False` の場合)。解が無いので、手書きの接線 (`user_defined_tangent`) は呼ばれず、自動微分の接線も計算されない |

## 2. 解き直し

自動微分の解法は、試行点 (σ_trial、Δλ = 0) から反復を始める。この反復が失敗したステップに限り、Δλ の初期値を変えて、同じステップを 1 回解き直す。失敗とは、Δλ < 0 の根に収束した場合、反復の上限に達した場合、ヤコビアンが特異であった場合である。

| 項目 | 内容 |
|---|---|
| 解き直しの初期値 | 試行点で、σ と Δλ のみについて Newton 法を 1 回適用したときの Δλ。implicit の状態を試行値に固定した見積もりであり、硬化を状態が担うモデルでは完全塑性の値になる |
| モデルごとの記述 | 不要である。初期値は残差のヤコビアンから作られ、Δλ の単位にも依存しない |
| 解く方程式 | 変わらない。解き直しで得るのは、同じステップの同じ残差の根である。増分の分割 (3 節) のような別の積分にはならない |
| 1 回目で収束するステップ | 影響を受けない。結果と反復の履歴は、解き直しの無い解法とビット単位で一致する |
| 記録 | `StressUpdateResult.n_restarts` が 1 になる。`n_iterations` と `residual_history` は、2 回分を持つ |
| 2 回目も失敗した場合 | 非収束である。扱いは `raise_on_nonconverged` に従う。2 回目が例外を送出した場合は、1 回目の結果を報告する |
| 手書きの解法 | 対象外である。`user_defined_return_mapping` はモデル自身の解法であり、UMAT が移植するのもこの解法である。フレームワークは結果を判定するのみで、反復には関与しない |
| 無効にする方法 | `PythonIntegrator(model, nr_restart=False)`。解き直しの有無を、同じ履歴で比較できる ([モデルを比べる](comparing.md) の 6 節) |

解き直しは、収束を保証しない。解き直しても収束しないステップには、刻みを細かくするか、増分の分割を用いる。

## 3. 増分の分割

`SubSteppingIntegrator(integrator, max_substeps=16)` は、収束しなかった増分を、2、4、8 … 分割して解く。

| 項目 | 内容 |
|---|---|
| 適用 | 明示的に integrator を包んだ場合のみ |
| 収束する増分 | 結果、反復回数、接線は変わらない |
| 分割した増分 | 分割数が `StressUpdateResult.n_substeps` に記録される。分割したステップは、分割前の増分の残差の根ではない (より細かい積分の結果である) |

詳細は `SubSteppingIntegrator` の docstring にある。

## 4. 値として受け取る

`PythonIntegrator(model, raise_on_nonconverged=False)` の場合、driver の動作は次のとおりである。

| メソッド | 動作 |
|---|---|
| `iter_run` | `converged=False` のステップを返し、停止する。収束していない反復値で状態を進めない |
| `run` | 完了したステップのみを返す。`result.converged` が `False`、`result.failed_step` が収束しなかったステップの番号になる。収束しなかったステップは、`result.stress` などの配列に含まれない |
